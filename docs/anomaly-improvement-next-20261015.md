# แนวทางปรับปรุงหลัง controlled Gemma → Qwen experiment

วันที่ 15 ตุลาคม 2026 — เป็นข้อเสนอสำหรับการทดลอง ไม่ใช่ผลยืนยันว่าปรับแล้วดีขึ้น

## หลักฐานที่มี

อ้างอิง `matched-gemma-gate-20261015.md` และผลดิบใน
`scratch/event-retrieval/matched-gemma-gate-20261015-v1/`:

- ทั้ง all-Qwen และ Gemma→Qwen ได้ TP=6, FP=1, FN=1 บน validation 7 เหตุ
- คำขอ Qwen ลด 19→16 เมื่อใช้ Gemma; assessment ของหน่วยที่ได้ตรวจร่วมกันตรงกันทั้งหมด
- เป็น UBnormal ภาพจำลอง ไม่มีเสียง และ normal exposure เพียง 60.13 วินาที ไม่รองรับข้อสรุปเรื่องการใช้งานจริงหรือ false alerts/hour ที่เสถียร

ตรวจผลรายหน่วยเพิ่มเติม:

1. `abnormal_scene_4_scenario_7`: เหตุที่มี label ช่วง 13.033–15.033s ถูกส่งให้ Qwen ในหน่วยท้ายแล้ว แต่ Qwen ตอบ normal ทั้งสองแขน การประเมินโดยไม่รวมช่วงก็ยังพลาดเหตุนี้ จึงแก้ด้วยการเปลี่ยน merge อย่างเดียวไม่ได้
2. `normal_scene_4_scenario_4`: Qwen แจ้ง suspicious โดยอ้างทั้งชุดสีแดงและการเดินที่ดูผิดธรรมดา พร้อมเสนอทางเลือกว่าคือ costume/avatar/performer นี่เป็นเหตุให้ตรวจว่าตัดสินจากรูปลักษณ์มากเกินไปหรือไม่ ไม่ใช่หลักฐานยืนยันว่าเสื้อผ้าคือสาเหตุทั้งหมด
3. Gemma เลือก 13/24 หน้าต่างจากวิดีโอปกติ และ 30/33 จากวิดีโอผิดปกติ (นับหน้าต่างต้นทาง ไม่ใช่จำนวนเหตุหรือหน่วย Qwen) ตัวกระตุ้นที่พบเป็น normality deviation จึงควรปรับคุณภาพคลังปกติและ calibration เพื่อประหยัดงานต่อ
4. Contact sheet หน่วยท้ายเป็นภาพมุมกว้าง การเคลื่อนไหวละเอียดมองยาก แต่จากภาพนี้ยังระบุชนิดเหตุไม่ได้แน่ชัด ห้ามใช้ label เวลา/กล่อง actor มาเลือกภาพให้ inference แล้วอ้างว่าเป็นการตรวจอัตโนมัติ

## ลำดับทดลองที่เสนอ

### A. เลือกหลักฐานตามเวลา ก่อนเพิ่มจำนวนเฟรมทั่วทั้งวิดีโอ

เก็บ baseline ช่วงไม่เกิน 12s และบริบทเดิม เปรียบเทียบ uniform sampling กับการจัดสรรเฟรมบริเวณยอดคะแนน Gemma/การเปลี่ยนแปลงภาพ โดยยังสำรองเฟรมครอบคลุมต้น–ท้ายและบริบทไว้ ใช้จำนวนเฟรมและงบภาพเท่ากันในแขนแรกเพื่อแยกผล sampling ออกจากผลต้นทุน

หาก Qwen ตอบ normal แต่หลักฐานคัดกรองยังสูง ให้ตรวจซ้ำแบบมีงบจำกัด: เลือกช่วงย่อยจากคะแนน inference เท่านั้น เพิ่มเฟรมเรียงก่อน–ระหว่าง–หลัง และทดลอง crop บริเวณที่เปลี่ยนแปลงควบคู่ภาพเต็ม ห้ามใช้ motion เป็นข้อบังคับ เพราะวัตถุวางทิ้ง/สภาพแวดล้อมบางชนิดอาจนิ่ง

ทดลอง sampling ก่อน แล้วจึงเพิ่ม crop เป็นอีกแขน ไม่รวมสองการเปลี่ยนแปลงจนระบุสาเหตุไม่ได้ งาน crop/motion ก่อนหน้ายังไม่ได้พิสูจน์ว่าดีกว่า baseline จึงไม่เปิดเป็นค่าเริ่มต้นทันที

แนวคิด adaptive frame allocation มาจาก Holmes-VAU แต่ระบบเต็มของงานนั้นมีการฝึก scorer/โมเดล เราจะยืมเฉพาะแนวคิดมาทดลองด้วยคะแนนที่มีอยู่ ไม่อ้างว่าเป็นการทำซ้ำ Holmes-VAU แบบไม่ฝึก

### B. ตรวจหลักฐานพฤติกรรมและคำอธิบายทางเลือก

คำสั่ง camera-normality เดิมมีข้อห้ามใช้รูปลักษณ์อย่างเดียวอยู่แล้ว การเพิ่มประโยคเดิมจึงไม่ใช่การแก้ใหม่ ให้ทดลองแยกผลเป็น:

- สิ่งที่เห็นและ timestamps
- การกระทำ/การเปลี่ยนแปลงของวัตถุหรือสภาพพื้นที่
- ความต่างจากตัวอย่างปกติที่เกี่ยวข้อง
- คำอธิบายทางเลือกและสิ่งที่ยังมองไม่เห็น

ถ้าเหตุผล suspicious อาศัยรูปลักษณ์และไม่มีหลักฐานการกระทำ/กฎพื้นที่/วัตถุที่เกี่ยวข้อง ให้ส่งตรวจซ้ำหรือคง uncertain แยกไว้ ไม่บังคับ normal และไม่ถือ uncertain เป็นการตรวจพบถูก ให้ normal ที่ขัดกับหลักฐานคัดกรองมีทางตรวจซ้ำด้วย แทนการเชื่อ confidence ของ Qwen อย่างเดียว

EventVAD สนับสนุนการแบ่งช่วงตามความต่อเนื่องของเหตุและการให้เหตุผลก่อนตัดสิน ส่วนงาน Reality Check รายงานความเอนเอียงไปทาง normal ของ MLLM แบบ zero-shot แต่ยังไม่ใช่ข้อพิสูจน์ว่าเป็นสาเหตุเดียวของ Qwen รุ่นที่เราใช้

### C. ทำคลังปกติให้ครอบคลุมเพื่อประหยัด Qwen

เพิ่มคลิปปกติที่ยืนยันแล้วจาก development ตามกล้อง แสง ความหนาแน่นคน และกิจกรรมประจำ จากเดิมที่มีเพียงสองคลิปปกติสั้นต่อฉาก รุ่นคลังและแหล่งข้อมูลต้องตรวจย้อนกลับได้

ปรับ threshold แยกช่องทาง/ฉากบน validation ที่กันไว้จากคลัง ไม่ใช้ระยะถึงตัวเองใน bank เป็นหลักฐานว่าปกติแยกได้ดี ไม่เพิ่มตัวอย่างเพียงเพราะ Qwen ตอบ normal และไม่ยก threshold ทั้งระบบเพื่อให้จำนวนคำขอลดลงโดยไม่ตรวจ recall

แยกเป้าหมาย C (ลดงานต่อโดยรักษา screening recall) จาก A/B (ปรับผลตรวจท้ายทาง) เพื่อไม่สับสนว่าการเรียก Qwen น้อยลงเท่ากับความแม่นดีขึ้น

## Protocol รอบถัดไป

1. ล็อก baseline และเก็บชุดเดิมเป็น regression ซึ่งถูกตรวจผลและใช้วิเคราะห์แล้ว ไม่เรียกว่า independent test
2. เตรียม development/validation ใหม่แยกตามการบันทึกและฉาก พร้อม normal exposure ยาวขึ้น รักษา official test ปิดไว้จนล็อก configuration
3. เปรียบเทียบ baseline, adaptive sampling, structured evidence, sampling+evidence ตามลำดับ บันทึกเฟรม/payload/ผลดิบ จำนวน retries และเวลาเพิ่มทั้งหมด
4. แยกการทดลอง crop และ normal-bank calibration เป็นแขนเพิ่มเติมเมื่อมีข้อมูลรองรับ ไม่เปิดทุกตัวพร้อมกัน
5. ทุกการตัดสิน retry/เลือกเฟรมใช้ข้อมูลที่ระบบเห็นจริงเท่านั้น ประเมินด้วย label ภายหลัง ไม่เลือกเฉพาะตัวอย่างพลาดที่รู้คำตอบแล้วมารายงานเป็นความแม่นรวม
6. รายงาน event recall/precision ที่ tIoU≥0.3, screening recall, false alerts/hour, uncertain, เวลา, จำนวนคำขอ และ RAM/VRAM พร้อมจำนวนตัวอย่าง แยกภาพจริง/จำลองและการมีเสียง
7. บน regression ให้ตรวจการรักษา 6 เหตุที่พบเดิมและการแจ้งผิดเดิม แต่การประกาศว่าดีขึ้นต้องดูชุดที่กันไว้ใหม่ด้วย ห้ามให้ผลดีเฉพาะเคสที่วิเคราะห์กลบ regression อื่น

ไม่แนะนำแบ่งทุกช่วงเป็น 3s: งานก่อนหน้าของเราใช้ 57 คำขอและได้ 4/7+1FP; หลัง schema retry รวม 75 คำขอได้ 5/7+2FP ยังด้อยกว่า baseline 12s จึงควรตรวจละเอียดแบบเลือกช่วงและรักษาบริบท
