# ผลทดสอบการคัดกรองด้วยข้อมูลที่มี label

วันที่ 8 ตุลาคม 2026 — บรันช์ `codex/embeddinggemma2-event-retrieval`

**ปรับให้ Gemma คัดช่วงที่ครอบเหตุได้ครบในชุดทดสอบเล็กนี้แล้ว แต่ระบบหลัง Qwen ยังพลาดเหตุ จึงยังไม่เปิดใช้แทนเกณฑ์เดิมในเว็บ** ไม่ได้ฝึกน้ำหนักโมเดลใหม่

ใช้ UT-Interaction วิดีโอต้นฉบับ 20 ไฟล์ รวมประมาณ 23 นาที พร้อมเวลาเหตุจากผู้จัดทำ แยกต้นฉบับเป็น development 12 / validation 4 / test 4 ไฟล์ ชุด test มีผลักและชกรวม 8 เหตุใน 85 ช่วง ทั้งนี้เคยประเมินคลิปสั้นจากต้นฉบับ test เหล่านี้มาก่อน จึงเป็น regression ไม่ใช่การทดสอบกับข้อมูลที่ไม่เคยเห็นเลย

| วิธีคัดช่วง | เหตุที่คัดช่วงมาครอบได้ใน test | ช่วงส่งตรวจ |
|---|---:|---:|
| เกณฑ์เดิม | 4/8 | 13/85 |
| อ้างอิงคลิปจริงและตรวจแบบเว้นต้นฉบับ | 5/8 | 19/85 |
| ผ่อนเกณฑ์คำอธิบายจาก development ที่เว้นต้นฉบับ | 8/8 | 43/85 |

“ครอบเหตุได้” หมายถึงมีผู้สมัครอย่างน้อยหนึ่งช่วงครอบเวลาเหตุอย่างน้อยครึ่งหนึ่ง ยังไม่ใช่ยืนยันเหตุหรือระบุขอบเขตได้ตรงทั้งหมด

วิธีอ้างอิงคลิปจริงเคยดูดีใน validation แต่ยังพลาดเมื่อเปลี่ยนต้นฉบับ จึงไม่ควรใช้ตัดช่วงทิ้งเพียงวิธีเดียว ส่วนเกณฑ์แบบผ่อนเหมาะสำหรับทดลองคัดกรองให้ไม่พลาดก่อน โดยลดจำนวนผู้สมัครจากตรวจทุกช่วงได้ 49.4% แต่ยังต้องยืนยันกับข้อมูลใหม่ จำนวนตัวอย่าง 8 เหตุยังน้อย

เมื่อนำช่วงไปให้ Qwen ตรวจจริง:

| ภาพที่ให้ Qwen | เหตุที่มีผลบวกครอบอยู่ในช่วงที่เห็น |
|---|---:|
| สูงสุด 8 เฟรมกระจายใน 6 วินาที | 3/8 |
| สูงสุด 8 เฟรมในช่วงกลาง 3 วินาที | 5/8 |
| เก็บผลบวกเดิม แล้วซูมตรวจซ้ำเฉพาะช่วงอื่น | 6/8 |

แถวสุดท้ายคำนวณจากคำตอบของการทดลองสองรอบที่วัดจริง ยังไม่ได้รันคิวแบบปรับตามผลครบอีกครั้ง การซูมใช้เวลาตรงกลางหน้าต่างตามกฎตายตัว ไม่ใช้เวลาเฉลย เหตุที่ยังพลาดสองเหตุเป็นชก ผลนี้ยังต่ำกว่าเป้าหมาย final Recall 85% และยังไม่ได้วัดการแจ้งผิดต่อชั่วโมงครบตามแผน

**ข้อสรุปที่ใช้พัฒนาต่อ:** Gemma ควรเก็บช่วงไม่แน่ใจไว้ส่งต่อ ส่วนการอ้างอิงช่วยจัดลำดับได้ การซูมเวลาดูมีประโยชน์กับ Qwen แต่ต้องมีทางสำรองเพื่อเก็บเหตุที่วิธีเดิมตรวจพบ และต้องทดสอบกับวิดีโอต่างกล้องที่ยังไม่ได้ใช้เลือกวิธี

ต้นทุนที่วัดได้: Gemma peak allocated VRAM ประมาณ 1.83 GiB; Qwen whole-card peak ที่สุ่มวัดประมาณ 11.28 GiB รวมโปรแกรมอื่นบนการ์ด การทดลอง Qwen สองรอบใช้ประมาณ 143 วินาทีต่อรอบ คิวซูมแบบสำรองเพิ่มจำนวนคำขอ จึงยังอ้างไม่ได้ว่าประหยัด Qwen ไปครึ่งหนึ่งจริง

ซอฟต์แวร์ผ่านการทดสอบเฉพาะส่วนที่เกี่ยวข้อง 42 ข้อ เก็บคำตอบดิบ ผลไม่แน่ใจ และค่าเกณฑ์ที่ล็อกไว้แล้ว ไม่มีการเปลี่ยนผล review ของผู้ใช้
